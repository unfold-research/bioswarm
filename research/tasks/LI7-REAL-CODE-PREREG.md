# LI7 preregistration: conflict geometry on real code, with a second model (2026-11-17)

**Status:** registered 2026-11-17 by the research lead after LI1 to LI6 and a two-case pilot (`results/li7-pilot/`, used only for cost, prompt and checker sanity; its cases are not reused). Claude **Sonnet 5.5** (effort low), Message Batches API, shared ledger ([US$ redacted] committed before this study). Config `observatory/batch2/rc/li7.json`, domain `observatory/batch2/rc/code.mjs`, runner `observatory/batch2/rc/run-rc.mjs`, analysis `observatory/batch2/rc/analyze-rc.mjs` (all committed before the main run). Study cap [US$ redacted] (`studyCapUsd`), enforced by the runner before each wave from actual spend plus the wave's reserve; the shared ledger's [US$ redacted] cap also binds.

## Why

LI1 to LI6 (Haiku 5.5, synthetic colouring and schedules) found that the geometry of a conflict decides the protocol: on **symmetric** conflicts (either side can fix it) simultaneous repair oscillates and one-side-acts cures it, while messaging does not; on **directed** conflicts (one side holds the target) messaging helps and forcing one side to hold hurts. Two open limits: synthetic tasks and one model. LI7 moves to executed JavaScript code and to Sonnet 5.5.

## Task

Each case is a codebase of k = 5 modules, M1 to M5, one member (developer) per module. Generated by `makeInstance(5, seed)`; the field is the executed test suite (node:vm, 200 ms per call, 6 tests per check):

- **local** checks: 2 functions per module, specified entirely to their owner;
- **directed** edges (5 per case): module A's function `f(s)` must call helper `h` of module B and combine its result; **only A's specification says what `h` must return**; B is told that `h` is defined by A's team. Only B can change `h`. The check attributes a failure to A alone (local) when `f` is wrong even with a correct `h` or does not use `h`'s result, otherwise to the edge (A and B). A member sees failing tests (inputs, expected, actual, what `h` returned) and the partner module's current code;
- **symmetric** edges (4 per case): A's `encodeR(rec)` and B's `decodeR(str)` must round-trip a record of three typed fields through a string restricted to `[a-z0-9|;,/~#+._=-]` (no JSON). The format is not fixed; each side is given a different house style, stated as a preference. Either side can fix the edge by adopting the other's format.

Cases: 12, seeds 7000 to 7011, shared round 0 (each member writes its module from its spec, no violations shown), then rounds 1 to 5.

## Arms

| Arm | Symmetric edge failing | Directed edge failing | Messages |
|---|---|---|---|
| `sync` | both modules act | both act | no |
| `inhibit` | one side, by a hash priority alternating with the round | one side | no |
| `chat` | both act | both act | yes (at most 3 per member, 40 words) |
| `routed` | one side | both act | yes |
| `solo` | one agent writes and repairs all five modules from all specifications (not paired with round 0) | | |

Local failures always go to their owner. An acting member returns its whole module.

## Hypotheses

Primary unit: a cross-module edge (S or D) that failed at least once in any arm, paired across arms on the same case; outcome: passing after the last round; exact two-sided McNemar on discordant edges.

- **H-LI17 (symmetric: one side acts).** `inhibit` resolves more symmetric edges than `sync`. Supported if discordant edges favour `inhibit` with p < 0.05; refuted if they do not favour it; otherwise inconclusive.
- **H-LI18 (directed: talk).** `chat` resolves more directed edges than `sync`. Same rule.
- **H-LI19 (directed: inhibition hurts).** `inhibit` resolves fewer directed edges than `sync`. Supported if discordant edges favour `sync` with p < 0.05; refuted if they do not.
- **H-LI20 (router).** `routed` resolves more cross-module edges than `inhibit` (p < 0.05) and no fewer than `chat`. Refuted if it resolves no more than `inhibit` or fewer than `chat`.
- **H-LI21 (one agent below capacity).** `solo` solves (all checks pass) at least as many cases as the best swarm arm.

Secondary, not tested for verdicts: per-case sign tests on final failing checks; oscillation (symmetric edges failing before a round in which both modules changed and still failing after); output tokens per case; messages; emergent use of code comments as a channel.
