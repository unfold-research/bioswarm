# Harness requirements for persistence (Autonomy programme, 2026-11-22)

What in the Colony today makes a swarm stop, give up or say "I do not know" before everything about a task has surfaced, and what the Colony must offer so that the Autonomy programme (`programs/autonomy.md`) can test and later ship a stopping rule. Written by Autonomy Research from a read-only audit of the Colony source at commit `f8f606a0033ca1ef621296cc42231fc2295b522f` (the local checkout on 2026-11-22; the lab studies pinned `e9b45f4b8f02323088881cb8f9eb7777032acd32` for LI39, so the Bancada should confirm each anchor on the commit it runs). Paths are in the `colony` repository. Prompts are in Portuguese; quotes are exact, with an English rendering in brackets. Delivery path: the Unfold Bancada takes these to the App Engineer; this programme does not change the Colony.

- R1: `limits` keys `ants`, `cycle`, `pair`, `refill` (`person`, `goal`, `never`), `goalTurns`, `goalMinutes`, `implicitGoalTurns`, `implicitGoalMinutes`, `stagnation`, `judgeFailures`, `conflict`, `finalConfidence`, `classifierDone`, `stallMs`, `silentMs`, `callMs`, `callChars`, `stallRetries`, `compactAt`; `null` is no limit, except `compactAt: null` (compacts at the window's edge) and `classifierDone: null` (the LLM judge always decides). Unknown keys are rejected. Correction to S3: the product already refills on goal continuations, so the default is `refill: goal`.
- R2: `autonomous: true` removes every "à pessoa" text, the judge does not treat a question as BLOCKED, person-only tools are not offered, and a plain-text question is logged (`tasks[].wouldAsk`, `totals.wouldAsk`) and nudged forward up to 5 times.
- R3: per goal `tasks[].goal.stop {reason, turn, at, by}`, `turnsUsed`, turns with their trigger (person, goal, ant); per run `stop {reason, at}`, first reason wins; the bench records `solved` or `cap` through `POST /lab/stop`. A judge "done" is recorded as `solved` with `by: 'judge'`, so the study's own check must override it. `exhausted` arrives only with R7.
- R4: `labIdle` is false while the judge or classifier is pending, the goal is active or reporting, or the nudge after a question runs.
- R5: `tasks[].modelCalls[]` with role, caste, weight, effort, input, output, thinking, cache, cost, provider and model; totals include thinking. The zero thinking in LI37 and LI39 was a missing sum, now fixed. Jev calls carry no tokens.
- R6: `effort {parent, light, normal, heavy, judge, classifier}`, each `off`, `low`, `medium` or `high`.
- R11 (accepted 2026-11-22, Colony `main` `ba2ce00`, `tests/lab-classifier-record.test.cjs`): per conversation `agents[].tasks[].classifier[]`, one entry per decision (`decision`: goal-first-pass, chat-assist or router; typed questions and answers with confidence; `provider` jev, model or null; returned and requested Jev `version`; the fallback `model {provider,id,effort}`; `jevKey`; attempts with durations; `action`, including `ended-goal-solved` or `called-llm-judge` with the judge's verdict; `goalTurn`, `turnSequence`, `at`); per run `classifier {jevKey, jev {enabled, version}, providers, decisions}`. `POST /lab/create` takes `jev: {enabled: false}` to switch Jev off for a run and `jev: {version: 'jev-1.14.0'}` to pin it. In lab runs only goal first passes and chat assist occur (the router does not run for project-agent conversations). Fixed with it: the runtime cleared `TYPESAFE_API_KEY` before reading it, so only the key file worked. Not tested against the real Jev API: the key is not on the lab boxes yet; decided by the Research Leader: Jev is off by default in the lab and on only when a spec asks for it (`bench.jev`), which keeps other programmes' runs comparable and allows a clean fallback-against-Jev arm.
- Not yet tested: thinking above zero with a real provider, and a real slow judge; both fit the first AU Colony pilot. The bench driver (`observatory/batch2/colony/drive.mjs`) still passes only `antLimits`; the Bancada wires the new fields with the first AU spec, which must pin `bench.colony` to `80dbe9f` or later.

The principle (owner, 2026-11-22): before the swarm says it cannot or does not know, every obvious and non-obvious option must have been considered, and the harness must not restrict that. So the only stops a persistence run should meet are (a) the task is solved or exhausted by a real check, and (b) a hard spend or time cap the study sets. Every other stop must be visible, configurable from the lab, and recorded.

## 1. What stops a swarm early today

| # | Mechanism | Default | Anchor | Why it ends work early |

On exhaustion the tool error says "Limite de 24 mensagens entre formigas neste pedido: junte o que tem e responda à pessoa." [24-message limit between ants for this request: gather what you have and answer the person.] This is the LI15 stall. |

There is no cost cap, tool-call cap or global run cap in the Colony; costs are only tracked (`tasks.cjs:1170` on). A persistence run therefore needs the study's cap enforced by the lab driver, which the bench already does for minutes.

## 2. Requirements

Priority 1 is needed before the first Colony persistence or team-size study; priority 2 before a stopping rule can ship as a default (programme level L5).

| Id | Priority | Requirement | Fixes | How the bench checks it |
|---|---|---|---|---|
| R1 | 1 | **Every limit settable per lab run**: `ants`, `cycle`, `pair`, budget refill policy, goal turns and minutes (explicit and implicit), stagnation, judge failures, final-answer conflict, classifier shortcut threshold, stall times and retries, `callChars`, compaction threshold. `null` means no limit. `ant_roster` and the run export report the values in force. | S1 to S4, S6 to S8, S12 to S15, S19 | a lab run with every limit set returns them in its export; a run with `ants: 16` spawns 16 |
| R2 | 1 | **Autonomous mode** (one lab flag): budget-exhaustion and stall texts never tell the model to answer or ask the person; they say to continue with what it can do, through the field or its own tools. `colony_ask`, confirmation prompts and gate "stop" prompts are replaced by "decide, record the assumption, continue". Every would-be question is logged as an event, with its text. | S1, S2, S13, S16 | grep of a run's prompts and tool errors finds no "à pessoa"; a forced budget exhaustion shows the run continuing |
| R3 | 1 | **Stop reason recorded** for every run and every goal: one of `solved` (the study's check), `exhausted` (alternatives gate passed), `blocked` (judge), `goal-turns`, `goal-time`, `stagnation`, `judge-failure`, `conflict`, `classifier-done`, `budget`, `idle`, `asked-person`, `cap`, `error`, with the turn and time. Goal turns used, and which turns ant messages started. | S4, S8, S11; needed by AU-R1's successors and the stop-reason measure | the export of every run has exactly one stop reason; a seeded run hitting each limit records the right one |
| R4 | 1 | **Idle means idle**: `labIdle` false while the goal judge or classifier is pending and while ant messages are queued; a plain-text question to the person in autonomous mode does not make the team idle (R2 forbids it, R3 records it). | S11 | a run where the judge takes 50 s is not ended by the idle detector |
| R5 | 1 | **Thinking tokens and effort per call in the telemetry**: input, output, thinking, the effort level and the role (parent, ant caste and weight, judge, classifier, router) for each model call. | S18 | lab export has thinking > 0 on a medium-effort run |
| R6 | 1 | **Effort per role settable per lab run**: parent, ants (per weight), judge, classifier, with `off`, `low`, `medium`, `high`. | S18 | export shows the configured effort on each call |
| R7 | 2 | **Alternatives gate before "cannot" or "do not know"** (the AU-P3 arm), selectable per run: a BLOCKED or "do not know" is accepted only when the answer lists the options tried, each with its evidence, and a separate check (another call, at the judge's effort) names at least one untried plausible option or confirms none remain; if it names one, the goal continues with it. The judge reads the whole answer or a structured list, not the last 6,000 characters. | S5, S9, S10, S17 | on a seeded solvable-by-a-second-route task, a first "cannot" is sent back with a named option |
| R8 | 2 | **Prompt variants selectable per run**: the default prompts, and a persistence variant without "seja conciso", "ENCERRE o seu turno" and the 12-line report limit, which asks the team to surface everything relevant, obvious and non-obvious, before reporting. Variants are versioned files the export names, so a study can compare them as arms. | S16, S17 | export names the variant; a diff of the prompts matches the file |
| R9 | 2 | **Continuation after "done"** (for AU-P4): the lab can start a fresh team on the same minimal statement with the first team's final output attached, in the same run record. | — | a two-stage run exports both stages |
| R10 | 2 | **Hard caps from the study only**: spend (US$ or tokens) and wall time per run, enforced by the Colony or the driver, the only stops besides `solved` and `exhausted` in a persistence run; reaching one records `cap`. | complements R1, since no cost cap exists | a run with a US$ cap stops within one call of it |
| R11 | 1 | **Every classifier decision recorded** in the lab export: which decision (router, goal first pass, chat assist), the typed questions, the answers with their confidences, the provider (`jev` with its model version, or `model` with its model and effort), the duration, and the action taken; plus whether a Jev key was present for the run. Pin the Jev version per run (the code asks for `jev-latest`; pin a fixed version such as `jev-1.13.0`). Content can stay redacted as `classifier.cjs` already does, as long as the decision can be joined to its turn. | S6, S7; the classifier front (AU-C1 to AU-C3) | a lab run's export lists each goal first pass with provider, confidence and duration |

S6 and S7 are classifier decisions: the goal judge's first pass is a typed question answered by TypeSafe Jev when a key is present, otherwise by the provider's fast model at the `router` role (`classifier.cjs` `createQuick`, `SURE.done` 0.9). Until `ba2ce00` the lab exports (checked on LI39's raw data) recorded no goal events, no verdicts and no provider. Settled on 2026-11-22: the two lab boxes on benchhost never had a Jev key, so in every lab run (LI15 to LI39) the goal first pass was answered by the provider's fast model at low effort, not by Jev. The six early stops in LI39 cannot be attributed to Jev; the suspects are that fallback or the LLM judge. the classifier design note (internal, not published) has the classifier front.

## 3. What this unblocks

- R1 (`ants`) and R3: the first team-size cell inside the Colony (AU-S1, AU-S2 at L3).
- R5 and R6: effort per role in the Colony (AU-E1 at L3), and thinking in every Colony economy table.
- R11: measuring the Colony's own stop classifier against the strict check (AU-C1 to AU-C3) on new runs.
- R2, R3, R4 and R10: a clean persistence baseline, where an unsolved run means the swarm ran out of moves, not that a soft stop fired (AU-P1, AU-P2).
- R7, R8 and R9: the persistence arms themselves (AU-P3, AU-P4).

Until these land, persistence work uses the batch instrument, where stops are the runner's own and already recorded, and AU-R1 reads the stop reasons of the existing Colony runs from their exports.
