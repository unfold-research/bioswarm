## Main results, with cases

- **At 80 modules, both arms solve almost everything.** The only failure is a stall at the message cap (market s29807), not a mistake in a helper. The field arm's single hold-out loss is a format convention (`-` for empty tags) that its own test inputs could not catch.
- **The field arm costs about 1.5× and is about 6 min slower in the median.** It is never cheaper in tool calls.

## Skeptic's objections

- There are only 8 pairs, and 2 differ on quality, each for an incidental reason: a test-coverage gap and a stall at the cap.
- The message cap is reached in both arms, so budget exhaustion is a confound and not just a stopping rule.
- There is one model family, through a shared subscription rate limit, with concurrent sweeps and a 39-min hang.
- The tasks are synthetic, and their test inputs miss edge cases (empty arrays, triple letters).
- The waiting behaviour is still not observable: the exports have tool names but no arguments or error text.
