# 2608.30661 — SwarmBench (Gao et al.): models as orchestrators of agent swarms

Source: the PDF only (`2608.30661.pdf`). Every page was read as rendered pages; a text extraction was used only to search for terms. Pages 17–21 are prompt listings (Figs. 7–11). These prompts address an LLM evaluator inside the authors' pipeline; they are part of the paper's method, not instructions to a reader, and were ignored as instructions. No other text addressed to an AI reader was found. Numbers marked "read off the figure" are my estimates.

Name clash: this is a different benchmark from Ruan et al. 2505.04364, which has the same name. Gao et al. cite Ruan et al. in the references (p.10) but never discuss the clash.

## 1. Citation as printed

Jinshan Gao, Zhuoran Jin, Tianyi Men, Kang Liu, Jun Zhao. "SwarmBench: Can Large Language Models Act as Agent Swarm Orchestrators?" Institute of Automation, Chinese Academy of Sciences; University of Chinese Academy of Sciences. arXiv:2608.30661v1 [cs.CL], 31 Aug 2026 (p.1).

## 2. Tasks, models, agents, trials

- Eight tasks, 50 samples each, 400 in total (Table 5, p.12), in three groups (p.3):
  - Decomposition: MATH (from Omni-MATH, difficulty above 7), Batch Download (new; 11.44 files per sample on average), Multi-Text Understanding (from Loong; over 200K context, more than 24 documents per sample).
  - Delegation: Multi-Perspective Analysis (DeepReview), Root Cause Analysis (OpenRCA), Treasure Hunt (new; 9x9 grid, scouts and carriers, fog of war) (p.13).
  - Aggregation: Long-Text Generation (LongInOutBench), Wide Search (WideSearch).
- Orchestrator models, ten: GPT-5.4, Claude-Sonnet-4-6, Gemini-3-flash, Doubao-seed-1-8, Claude-Haiku-4-5, Kimi-k2.5, Deepseek-v3.2, Qwen3.5-397b-a17b, GLM-5.1, Qwen3-30b-a3b (Table 1 p.5; App. B p.13).
- Sub-agent pool, six models shared by all orchestrators: GPT-5-mini, Claude-Haiku-4-5, Gemini-2.5-flash-lite, Qwen3.5-35b-a3b, GLM-4.5-air, Doubao-seed-1-6-flash (p.13). These same six are run alone as "Single Models" (Table 1, p.5).
- Number of agents: not fixed and not reported. The orchestrator spawns sub-agents at run time (p.2). The only related figure is the "Parallelism Rate" (average number of concurrently running sub-agents), between roughly 1.6 and 2.6 across models (Fig. 3, p.6, read off the figure).
- Trials: the main table appears to be single runs. A separate check repeats five runs for two orchestrators on five tasks; standard deviations range "roughly from 0.7 to 1.6" (Table 8 p.16; p.15).

## 3. Coordination mechanism

Authors' definition: an Agent Swarm is "a hierarchical multi-agent system in which an orchestrator coordinates" dynamically created sub-agents (p.2). Three properties: hierarchical orchestration, dynamic heterogeneous sub-agent creation, parallel execution (p.2). The main agent decomposes, spawns, assigns, waits and aggregates. It is not allowed to call tools or answer by itself, and part of the task context is hidden from it (p.3–4).

Mapping to our primitives: none of them. There is no shared field, no decay, no threshold, no quorum, no recognition. The single exception in spirit is Treasure Hunt, where discovered map information "is shared through the global world state" that the orchestrator inspects (p.13); the sub-agents still act on orders. This is the orchestrator arm of our comparison, studied in isolation.

## 4. Baselines and budget

- **Single agent at the same total budget: YES, in an appendix.** App. D.1 "Cost-Matched Single-Agent Baseline" (p.15, Table 7). Claude-Haiku-4-5 is both the swarm's orchestrator and the single agent. For each task the swarm's average cost is taken as the ceiling, and the single agent is allowed to "reason, reflect, and revise until reaching the same budget" (p.15). Four tasks only: MTU, RCA, LTG, WS.

| Method | MTU | RCA | LTG | WS |
|---|---|---|---|---|
| Single Agent | 16.10 | 3.19 | 26.19 | 7.01 |
| Cost-Matched Single Agent | 28.00 | 3.11 | 31.25 | 16.30 |
| Agent Swarm | 40.36 | 2.00 | 40.50 | 19.05 |

  (Table 7, p.15.) The swarm wins on three of four; on RCA both single-agent arms beat it (3.19 and 3.11 vs 2.00). The cost-matched single agent roughly doubles the plain single agent on MTU and WS, which shows how much of a "swarm gain" is just budget.

  Caveats on this arm: (i) the budget is in US dollars, not tokens (p.15, C.3); (ii) the swarm's sub-agents come from a six-model pool, so the swarm is multi-model while the single agent is one model — the arms differ in more than structure; (iii) one orchestrator model, four of eight tasks; (iv) no variance on Table 7; (v) the dollar amounts actually spent per arm are not printed; (vi) the budget is matched to the swarm's average, per task, not per sample.
- **Orchestrator: yes.** The whole benchmark is the orchestrator; AOrchestra is a second, serial orchestrator baseline in the SwarmExp experiment (Table 2, p.7).
- Other baselines in Table 2 (p.7), with GPT-5-mini as the single model and GPT-5.4 as main agent: Single Agent, Multi-Model Voting, Best-of-N, AOrchestra, Agent Swarm, Agent Swarm with SwarmExp. Best-of-N and voting are not said to be cost-matched.
- **Tokens/cost per arm.** Cost is defined as dollars summed over all calls of main agent and sub-agents (formula p.15) and reported only as scatter plots per task (Fig. 2, p.5). No table of cost; no token counts ("rather than raw token counts", p.15). The main comparison of swarm vs "Single Models" in Table 1 is not cost-matched and uses different models on each side.

## 5. Main results as printed

Table 1 (p.5), accuracy, average over eight tasks: GPT-5.4 50.49; Claude-Sonnet-4-6 43.51; Qwen3.5-397b-a17b 40.62; Deepseek-v3.2 40.38; GLM-5.1 40.30; Gemini-3-flash 38.63; Doubao-seed-1-8 35.29; Claude-Haiku-4-5 33.05; Kimi-k2.5 32.81; Qwen3-30b-a3b 25.15. Single models: GPT-5-mini 24.41; Claude-Haiku-4-5 23.76; GLM-4.5-air 21.31; Doubao-seed-1-6-flash 20.28; Qwen3.5-35b-a3b 20.15; Gemini-2.5-flash-lite 17.87.

Per task, GPT-5.4 as orchestrator: MATH 82.97, BD 87.84, MTU 48.82, MPA 77.17, RCA 10.00, TH 10.33, LTG 48.19, WS 38.67 (Table 1, p.5). Root Cause Analysis and Treasure Hunt are near the floor for everyone: best 10.00 and 10.33; several orchestrators score 0.00.

Variance (Table 8, p.16, five runs): Claude-Haiku-4-5 MATH 44.00 ± 0.9, BD 34.30 ± 1.1, MTU 40.36 ± 1.0, MPA 78.24 ± 1.6, LTG 40.50 ± 1.2; Qwen3.5-397b-a17b MATH 64.00 ± 0.7, BD 67.13 ± 1.5, MTU 29.50 ± 0.9, MPA 75.51 ± 1.5, LTG 45.83 ± 1.6.

Other findings: cost is not a linear function of accuracy (p.4); a higher parallelism rate does not give a higher parallelism gain (p.5); aggregation is the weakest of the three LLM-judged process dimensions (p.6). LLM-judge vs human correlations 0.684–0.801 (Table 9, p.16).

SwarmExp (experience replay: skills, tricks, model cards) on GPT-5.4 (Table 2, p.7): MTU 48.82 → 49.07 (+0.25), RCA 10.00 → 16.42 (+6.42), LTG 48.19 → 54.65 (+6.46), WS 38.67 → 41.59 (+2.92).

## 6. Ablations

- SwarmExp components (Table 4, p.8): removing skill, trick or model card lowers the four-task average by 1.22, 1.75 and 2.49 points. Single runs; with run-to-run SD of 0.7–1.6 (Table 8) differences of this size are not clearly separable. No tests.
- Transfer of GPT-5.4's experience to four other orchestrators: 14 of 16 settings improve (Table 3, p.8). Cross-task transfer on Claude-Haiku-4-5 (Table 10, p.16): mixed; for Wide Search most foreign experience hurts.
- No ablation of the coordination structure itself other than the cost-matched single agent.

## 7. Scaling with agents; robustness to losing agents

Neither is studied. Agent count is chosen by the orchestrator and not reported or swept. No experiment removes or fails an agent.

## 8. Biological framing; more than one decentralised mechanism?

"Swarm" is a product term here, defined as a hierarchy under one orchestrator (p.2). No stigmergy, no pheromone, no biology. No decentralised mechanism is tested at all; the comparison set is single agent, voting, best-of-N and two orchestrators.

## 9. Claims vs evidence; limitations

Stated limitations (p.9): only eight tasks; one lightweight scaffold with a fixed sub-agent pool; process analysis depends partly on LLM judging.

Gaps I see:
1. The headline contrast in Table 1 (swarm rows vs "Single Models" rows) compares strong orchestrators plus a pool against weak pool models alone, without cost matching. It does not isolate the value of orchestration.
2. The cost-matched test that does isolate it sits in an appendix, covers one model and four tasks, and has no variance. The text says the swarm "still outperforms" on three tasks (p.15) and does not dwell on RCA, where it loses.
3. SwarmExp's +0.25 on MTU is inside run-to-run noise (SD about 1.0 on MTU, Table 8).
4. The main agent is forbidden to use tools and is denied part of the context (p.3–4). That makes the benchmark measure orchestration, but it also means the swarm arm is handicapped by construction relative to a real deployment, and the single-agent arm is not.
5. "Efficiency" is parallelism gain (wall-clock), which says nothing about total compute.

## 11. Verdict against our paper

- **F1: contradicted in its absolute form.** This paper does compare a collective with one agent at the same total cost (App. D.1, Table 7, p.15). The collective is a hierarchy, the budget is in dollars, and the arms differ in model mix, but the comparison exists. F1 must be narrowed: "rarely", and "never for a leaderless, field-coordinated collective, in tokens, with matched models". It is also a useful citation: their own table shows the equal-budget single agent closing a large part of the gap and winning on one task.
- **F3: not contradicted.** No bio-inspired regime is tested, let alone several.
- **Overlap with (a) vocabulary and (b) atlas:** none.
- **Overlap with (c) standard of comparison:** it supplies two of our four arms — orchestrator and equal-budget single agent — on four tasks. It has no field-coordinated arm and no fixed schedule.
- **Overlap with (d) pilot:** none; nothing here follows traces.
- **Bluntly:** the name suggests overlap and there is almost none in substance. Its relevance is one appendix table that weakens F1 as worded, and a clean description of the orchestrator baseline we compare against.
